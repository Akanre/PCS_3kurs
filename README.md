**1. Анализ предметной области** 


Мы создаем цифровой каталог для коллекционера, который заменяет бумажные списки или записи в заметках. Это не просто галерея фото, а система учёта коллекционных предметов со своей логикой.

Ключевые сущности и правила:

•	Главный объект: "Игрушечная машинка". Экземпляр коллекции.

•	Атрибуты машинки:

      o	Фотография: Самый важный элемент для идентификации. 
  
      o	Название модели (обязательно): Основной текст для поиска и идентификации (например, "Ford Mustang Shelby GT500 1967").
  
      o	Комментарий/Описание: Место для личных заметок: где куплен, состояние, особенности, серийный номер, эмоции ("Подарок на 10 лет").
  
      o	Статус "Избранное": Машинка может находиться в общем каталоге и одновременно быть в избранном. Это не отдельная коллекция, а фильтр/метка.

•	Пользователь (Коллекционер): Владелец коллекции. Его данные нужны для персонализации и будущего расширения (например, обмена с другими коллекционерами).

•	Основные процессы:

      1.	"Я как коллекционер хочу быстро добавить новую машинку в каталог, просто сфотографировав её на телефон" -> Процесс захвата фото (камера/галерея) и создания карточки.

      2.	"Я хочу быстро найти машинку по названию модели, чтобы показать другу" -> Процесс поиска.

      3.	"Я хочу отметить свои топ-10 машинок, чтобы открыть приложение и сразу ими любоваться" -> Процесс добавления/удаления из избранного.

      4.	"Я хочу знать, сколько всего экземпляров в моей коллекции, чтобы похвастаться" -> Процесс агрегации и отображения статистики.

•	Ограничения/Бизнес-правила:

      o	У одной машинки должен быть хотя бы заголовок (название модели) и фото.

      o	Пользователь уникален и имеет доступ только к своей коллекции (логин/пароль).


**2. Описание стека технологий**


| Слой               | Технология                  | За что отвечает                                                  | Почему для этого проекта                                                                                                                                      |
|--------------------|-----------------------------|------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Frontend           | Flutter / Dart              | Вся логика отображения, навигации, интерфейса.                   | Кроссплатформенность, богатые UI-возможности, скорость разработки.                                                                                            |
| Backend            | Supabase                    | База данных, аутентификация, хранилище файлов, API.              | Бесплатный,тариф, простота интеграции с Flutter (supabase_flutter), сразу даёт готовую,аутентификацию и реальную БД, идеально для учебных/небольших проектов. |
| База данных        | PostgreSQL(внутри supabase) | Хранение структурированных данных: пользователи, машинки, связи. | Надёжная, SQL-совместимая, работает в Supabase.                                                                                                               |
| Файловое хранилище | Supabase storage            | Хранение фотографий машинок.                                     | Интегрировано с аутентификацией, простой API для загрузки/скачивания.                                                                                         |


**3. Детальный функционал**


**1. Модуль аутентификации**

    • Регистрация (Email + Пароль).

    • Вход (Email + Пароль).

    • Выход (Logout).

**2. Главная страница ("Моя коллекция")**

AppBar:

    • Заголовок "Моя коллекция"


Тело страницы:

Поиск по названию моделей

BottomNavigationBar с 3 иконками:

      • Главная (активная)

      • Избранное

      • Личный кабинет


GridView (2 колонки) с карточками машинок

Карточка:

    • Фото (заполняет всю ширину карточки)

    • Название модели (под фото, жирным шрифтом)

    • Комментарий/описание (под названием, если есть)

    • При нажатии на карточку - переход на экран редактирования машинки

Floating Action Button (FAB):

    • Кнопка "+" в правом нижнем углу
    

**3. Страница добавления/редактирования машинки**

    • Превью фото (сделанного/выбранного)

    • Поле "Название модели" (TextField, обязательное)

    • Поле "Комментарий/описание" (TextField с многострочным вводом, необязательное)

Кнопки:

    • "Сохранить" (сохраняет машинку в БД и возвращает на предыдущий экран)

    • "Отмена" (возвращает на предыдущий экран с подтверждением, если есть несохранённые изменения)


**4. Страница "Избранное"**

AppBar: Заголовок "Избранное"

Тело страницы:

    • Аналогичная главной странице GridView (2 колонки)

    • Отображаются только машинки с is_favorite = true

    • Карточки такие же как на главной

    • FAB отсутствует (добавление только через главную страницу)

**5. Страница "Личный кабинет" (Profile)**

AppBar: Заголовок "Профиль"

Тело страницы:

    • Приветствие: "Привет, [Имя]!"

Информация о пользователе:

    • Email
    
Статистика:

    • "Всего машинок: X" (кружок с цифрой или просто текст)

    • Кнопка "Выйти" - внизу экрана, красного цвета, с подтверждением
